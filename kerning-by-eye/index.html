Kerning by eye

When you type a headline, the browser spaces it using the font's built-in kerning table: a list of letter pairs, each with a fixed adjustment, chosen by the type designer for reading sizes. It's usually right. But it can't see the whole word, doesn't know how big the type is, and can't tell when a gap spells a different word. These are the moments a graphic designer overrides it.

Each example shows the browser's own layout next to a hand-respaced version. Blue figures are the designer's adjustments in 1/1000 em, the unit InDesign and Illustrator use for kerning.

How this page works

The Original panel is plain HTML text. The browser lays it out with the font's own kerning (font-kerning: normal) and nothing else, apart from the tight tracking the designer asked for in the "kerning" example.

For the Respaced version, the page measures where the browser put each character and redraws each one at that exact spot, shifted by the designer's adjustment. So in flip mode, the resting state is the browser's layout and hovering slides each letter by its adjustment. The adjustments are editorial judgement, tuned by eye. Another designer would choose slightly different numbers, and that's the point.
